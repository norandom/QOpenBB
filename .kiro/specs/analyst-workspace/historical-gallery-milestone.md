# Reopen a historical chart gallery

Status: HG0 source foundation accepted, 2026-10-27; HG1/HG2 implementation in progress. Deliver a saved, redeployable FMP gallery that lets an analyst choose a chart, inspect its financial meaning, and reproduce the same observations. The owner requested an overview screenshot in README and a linked guide with one screenshot and explanation per chart. This contract covers that bounded delivery under [prototype-first delivery](../../steering/delivery-workflow.md); it does not close the analyst-workspace specification or other chart callers.

The working audience assumption is that financial engineers value reproducible observations and explicit transformations over visual variety alone. The guide sits beside the gallery workflow; independent review should try to disprove its claims. The proposal fails if an analyst cannot find the gallery, distinguish reported from derived values, or recover an edited dashboard after restart. A pending screenshot or passing data endpoint is not application acceptance.

## Frozen asset and runtime boundary

Use two generated, versioned files under `contracts/gallery/`. Existing `contracts/widgets.json`, `contracts/apps.json` and their three-financial-binding validation remain unchanged. Generator logic is maintained and capped; generated JSON exclusions must identify that generator. Do not fetch during build, application startup, refresh or dashboard reopening.

`data.json` has exactly `{schemaVersion: 1, snapshotId: "fmp-historical-2025-01-v1", sources: [...], datasets: {...}}`. Each source has `id`, `provider`, `endpoint`, credential-free `parameters`, `retrievedAt`, `sha256`, and `limitations`. Each dataset has exactly `results` (ordered flat row objects) and `metadata`. Metadata has `id`, `title`, `sourceIds`, `observationStart`, `observationEnd`, `columns`, `transformation`, and `limitations`. A column has `field`, `type` (`string`, `date`, or `number`), `unit` (explicit text, including `category`), and `label`. Observation dates are ISO date strings; `retrievedAt` is an ISO timestamp retaining the source timezone. `transformation` is a string; dataset and source `limitations` are lists of strings. Numbers are finite JSON numbers, missing values `null`; calculations use unrounded values. Keys, row order, column order and serialization are deterministic. Include source hashes without local private paths or credential-bearing URLs.

`catalog.json` has exactly `{schemaVersion: 1, snapshotId: "fmp-historical-2025-01-v1", widgets: {...}, apps: [...]}`. `widgets` and `apps` use the current native discovery schemas. Use widget IDs `qopenbb_gallery_<chartType>` and one stable app name `QOpenBB Historical Chart Gallery - January 2025`; app customization stays enabled. Each widget is a normal `table`, has `data.dataKey: "results"`, explicit typed column definitions, and a fixed relative endpoint `/gallery/data/<datasetId>`. No provider credentials or required symbol entry is needed for this packaged data. The connector handles the existing `/data` origin prefix. Metadata is available in the response and financial meaning is carried into visible names/labels and the guide.

`GET /gallery/data/{datasetId}` returns exactly the selected `{results, metadata}`. Only enumerated dataset IDs resolve; unknown IDs return HTTP 404, and paths never become filesystem selectors. Register this route before the upstream `/` mount. A small `qopenbb_data/gallery.py` loader validates packaged version/IDs and composes the two discovery responses with the canonical catalogs. Duplicate widget IDs, duplicate app identities, broken dataset references, or malformed packaged assets fail explicitly rather than silently replacing a canonical entry. Preserve canonical ordering and content; append the gallery. Missing gallery assets are a packaging failure, not an empty successful gallery.

`pipeline/qopenbb_ci/runtime_inputs.py` explicitly allowlists both JSON files and the new runtime module. The existing Dagger copy of `runtime/contracts` into `/app/qopenbb_data/catalog` carries `gallery/`; add no broad repository copy. If an actual packaging test shows the current copy is insufficient, the controller owns the smallest reviewed `.dagger/src/qopenbb/data_api.py` change. Generation runs as a portable command before staging; Dagger only builds images.

## Financial projection boundary

The following dataset IDs and semantics are fixed. HG0 freezes exact column names, ordering and native saved-state payloads in the companion contract fixture before parallel implementation. Projection and template workers may not independently invent those fields. The [analyst guide](../../../docs/chart-gallery.md) owns expanded reader explanations.

| Dataset ID | Required projection and use |
| --- | --- |
| `january-prices` | Daily closes for 2025-01-02..2025-01-31, chronological dates and six named series, USD/share. Line uses the six series; Area selects Apple. Preserve trading dates. |
| `monthly-returns` | October 2024..January 2025 by symbol. `100 * (last close in month / last close before month - 1)` percent. Grouped Column/Bar select January; Heatmap uses symbol, month and return. |
| `daily-returns` | October 2024..January 2025 repeated observations by date, month and symbol: `100 * (close / previous trading-day close - 1)` percent. September 30 provides the initial base. Histogram selects Apple; Box Plot and Range Bar group by symbol; Range Area groups Apple by month. |
| `january-relationships` | One row per symbol: X sample standard deviation of January daily returns, Y January monthly return, and Bubble size mean January `close * volume` in USD/day. SD uses `n-1` and is not annualized. Size is a trading-activity proxy, not market capitalization or executed notional. Scatter uses constant marker size. |
| `revenue-components` | AAPL FY2024 quarters with cost of revenue and gross profit in USD billions. Their sum equals reported revenue before scaling. Nightingale and all stacked/normalized Cartesian examples use these disjoint components; normalized values divide by their sum. |
| `latest-revenue-components` | AAPL FY2025 Q1 cost of revenue and gross profit, USD billions, for Pie/Donut. Do not stack overlapping revenue and income measures. |
| `seasonal-revenue` | Q1..Q4 categories with AAPL FY2022, FY2023, FY2024 revenue series in USD billions. Radar compares the same unit on every spoke; Radial Column/Bar select FY2024. |
| `revenue-hierarchy` | AAPL FY2024 quarter/component paths, with only disjoint cost/gross leaves in USD billions. Treemap/Sunburst derive parents from leaves without double counting. |
| `income-bridge` | AAPL FY2025 Q1 ordered signed steps: revenue, minus cost, minus operating expenses, plus signed other income/expense, minus tax. Ending total equals net income exactly in original USD. The native caller accepts signed movements, not total/subtotal bars. Its ending balance must equal net income; reported subtotals are checks, not extra movements. |
| `revenue-flow` | AAPL FY2024 sum of quarterly revenue -> each quarter -> that quarter's cost/gross components. Each internal node conserves value; USD billions. Label it a derived income allocation, not cash flow. |
| `income-levels` | AAPL FY2025 Q1 revenue, gross profit, operating income, income before tax and net income, in that order, USD billions. Funnel/Cone/Pyramid compare overlapping reported levels; summation, conversion and allocation interpretations are invalid. |
| `income-combinations` | AAPL FY2024 Q1..FY2025 Q1 revenue and net income, USD billions, plus reported basic EPS, USD/share. Preset Column/Line and Area/Column use the first two on one axis. Custom uses revenue columns and net-income line left, EPS line right, with explicit assignments. |

For Box Plot, independently verify the current `(n-1)*p` interpolated quartiles and observed min/max whiskers. For Histogram, HG0 records saved bin count/edges and boundary inclusion from the existing caller; check counts sum to the included observations. Ranges represent min/max of repeated daily returns, not OHLC or confidence limits. Monthly returns are compounded price changes, not sums of daily returns. Missing preceding prices and fewer than two volatility observations must remain missing and visible. Keep source-to-derived reconciliation at full precision; formatting occurs last.
