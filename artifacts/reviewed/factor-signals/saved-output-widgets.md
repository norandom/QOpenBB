# Saved-output widgets

Financial modeling task 8.2 adds signed `widgets.json` and `apps.json` discovery to the internal modeling listener. The generated app binds a generic saved-output table to the `results` array of a GET. Its required text parameters are the existing run ID and output ID. The optional expected run ID lets a caller mark a previously selected result as stale. Each lookup reads the original run under its authenticated owner.

The saved verification status and selection freshness are independent. A withheld value remains null and keeps the explanation of the checks that affected it. A saved decimal always has exact text when a value exists. A numeric display value is available only when conversion to binary64 has zero absolute error. For example, −12.5 is available in both forms, while −0.1 is retained as exact text. The table uses literal text fields, including check explanations and a detail reference relative to the modeling connector base. The authorized run contains the trace and full evidence.
