## Category circles: exact source mapping

E2193-2230 (`RadiusCategoryAxis`) sets circle shape. `prepareGridPathTickData` reverses tick data. For each tick, let k be reversed domain index (domain length-1-indexOf(tick)). `getTickRadius` returns H=R*innerRadiusRatio when k=0; otherwise `inset + step*(k-.5) + bandwidth/2`. This uses the original category scale's signed descending range [R,H], established by C49704-49724. It is not a circle at the category label center or at each numeric value tick.

C12382-12407 gives the scale values: with N>1, `step=(H-R)/max(1,N-paddingInner+2*paddingOuter)`; `inset=R+((H-R)-step*(N-paddingInner))/2`; `bandwidth=step*(1-paddingInner)`. With N=1, effective paddingInner=0 and `step=(H-R)*(1-2*paddingOuter)`. For a singleton only the k=0 hole circle exists. Preserve this case and do not divide by N=0.

Default Bar (E38641-38646) has innerRadiusRatio=.2, groupPaddingInner=.2, paddingInner=.2, paddingOuter=.1. N=4 therefore yields circles at .2R,.4R,.6R,.8R, and the existing angle-axis outline supplies R separately. At R about234, those internal boundaries are about46.8,93.6,140.4,187.2px. Series group padding changes subdivisions within category bands; it must not move the category-boundary circles.

E2033-2103 (`RadiusAxis.updateGridLines`) cycles grid styles by the reversed tick order, uses `gridLine.width`, `stroke`, `lineDash`, no fill, and draws full-circle paths for a full angular range. The grid belongs behind marks. Default inherited grid is enabled, width1, solid lineDash[] using `gridLineColor` (C26401-26417). Radius-category overrides only positionAngle0 and line.enabled=false, retaining the enabled grid (C26868-26874). Angle-number defaults disable its radial-spoke grid via DEFAULT_GRIDLINE_ENABLED in C26861-26865; do not accidentally enable spokes.

Resolve grid color through existing `application/effectiveAppearanceColors.ts:applicationColors`, which already derives the original theme gridLineColor. Do not hardcode light gray: light default interpolates foreground toward background with ratio .9, dark with .743 when no resolved custom color exists. Preserve saved family/root axis grid overrides through the same appearance-composition precedence as the Column owner's new numerical-grid path. Category grid must read `radius-category.gridLine`, never `radius-number`.

Minimal shared contract addition is a distinct `categoryGrid` style and `categoryGridRadii` prepared field (or a controller-reviewed axis-tagged grid equivalent). Reusing a field named numericalGrid for category geometry would misstate ownership and risk applying Column rules. Preserve existing axis thickness/color editing for actual axis lines; retain original default disabled radial category line and do not draw the top ray solely because a line primitive exists. ## Radius gap: cause and safe correction

Original C49729-49781 starts from half the smaller available series dimension, computes real axis/series label boxes, then refines five times (last two permit hiding). `refineCircle` C49783-49839 derives left/right/top/bottom overhang beyond the current circle, symmetrizes opposing sides, and chooses `min((width-horizontalPadding)/2,(height-verticalPadding)/2)`. A minimum circle ratio .5 bounds excessive shrink. SeriesArea padding is already removed before this routine (C49691-49701).

Original AngleAxis E1168-1192 positions angular labels at `R+label.spacing+tick.size`. In inherited defaults spacing5 and tick.size6 give R+11 even when tick marks are disabled. E1253-1290 aligns fixed labels by quadrant: right side left-aligned, left side right-aligned, top bottom-baseline, bottom top-baseline, exact horizontal middle and exact vertical center. Its measured boxes, not a uniform margin, feed circle fitting. Parent category labels remain inside the circle and normally do not demand perimeter reservation.

Current `echarts/radialLayout.ts:geometry` instead takes max(category text halfwidth+22, numerical extent text halfwidth+22, height of '0123456789'+22), subtracting that single number from both half-dimensions. `axisLabels` puts all angular labels at R+22 and `radialChrome.ts:labels` center-aligns/middle-baselines all labels. Thus the vertical limit reserves wide horizontal-text margin even where only the small top/bottom label height matters. The supplied nearly square chart has a smaller series height after legend reservation, so this over-reservation plausibly accounts for the approximately 16px gap. This is a source-supported causal diagnosis, not proof that one constant reproduces every viewport.

Bounded recommendation: add a Bar-only pure layout helper that places its actual formatted angular ticks with the original R+11 and quadrant alignments, measures their actual font boxes, computes symmetric horizontal/vertical overflow independently, and performs a small bounded fit iteration in the existing available rectangle. Return center/radius plus alignment/baseline-aware angular anchors; paint consumes them without re-fitting. Include any visible category-label overflow, but do not reserve all category widths outside R unconditionally. Keep existing caption/legend padding and all numerical/domain/grouping owners. Use existing text measurement. No generic PolarChart clone, shared cartesian relayout or full collision/hiding redesign is necessary for this bounded appearance change.

For nonfixed orientations, either implement corresponding source alignment/rotation from E1234-1290 in the same bounded helper, or preserve the existing path and explicitly restrict the accepted correction to fixed labels until reviewed. Never silently change saved Parallel/Perpendicular behavior. Do not tune on one screenshot with `radius += 15` or a family-wide `room -= 15`: long labels, narrow viewports and changed units would clip. Owner comparison must still check the new radius and labels.

## Concrete one-pass Bar fit amendment

For fixed angular labels, the source's anchors are affine in R, so fit them directly rather than cloning its iterative layout. Freeze a helper input with: available series rectangle after captions/legend/outer padding; formatted angular tick labels and their angles in radians (top tick -pi/2); measured width/height per label; angular offset d=11 from resolved spacing5+tick-size6; category labels with their existing in-circle radial fractions; hole ratio. Output finite center/R/H and angular anchors carrying `align` and `verticalAlign`. Parent owns the source-resolved offset and formatted values. Helper does not compute domains, ticks, grouping, currency formatting or saved options.

For each angular label let c=cos(theta), s=sin(theta), W/H its measured text dimensions, and A/B the available rectangle halfwidth/halfheight. Normalize near-zero c/s consistently (a small numerical epsilon). Source fixed alignment puts horizontal outward text extent W beyond the anchor when c is nonzero, otherwise W/2; vertical extent H when s is nonzero, otherwise H/2. Its bounding constraints are:

- If abs(c)>epsilon: `R <= (A-W)/abs(c)-d`; otherwise require W/2<=A.
- If abs(s)>epsilon: `R <= (B-H)/abs(s)-d`; otherwise require H/2<=B.
- Always `R <= min(A,B)` and R>=0.

Choose the minimum finite upper bound and min(A,B), bounded below by0. Emit x=(R+d)c and y=(R+d)s; align left for positive c, right for negative c, center at zero; verticalAlign top for positive s, bottom for negative s, middle at zero. This directly satisfies symmetric source-style label overflow constraints for fixed unrotated labels; the current all-centered R+22 contract is removed only for Bar. Measure actual text boxes rather than assuming CSS line-height equals canvas ink. Internal category labels also receive a bounded check using their source-matched right-aligned top-ray placement and measured bounds. If they cannot fit, report that limit rather than hiding data or growing beyond the rectangle.

No arbitrary +15 and no copied five-pass solver are required. For an original-relative fit that only uses existing centered measurement APIs, one or two deterministic recomputations of measured boxes are acceptable, but must use the same constraints and produce stable finite bounds. Parallel/perpendicular labels require rotated box corners with the source anchor/alignment; controller can retain the existing orientation path until that separate mapping is reviewed, stating the bounded fixed-label visual scope. Do not claim complete original collision handling. Very small charts may differ from AG's minimum-radius floor; retain readable/error behavior and document that limit instead of drawing known clipped labels.

Legend reservation must use the same native layout as painting. Horizontal single-row width is sum(markerSize+markerGap+measured label width) + (N-1)*horizontalSpacing; default two-item gap32, marker11, markerGap5. Row height is max(markerSize,textHeight), with verticalSpacing between rows and no trailing vertical item padding. Side legend width for one column is max(markerSize+markerGap+textWidth), not max(textWidth)+30; its occupied height is sum(item heights)+(N-1)*verticalSpacing. Add legend.spacing between the occupied legend rectangle and plot. Keep the existing reservation when scroll/pagination or wrapping makes this simple single-row/column bound inapplicable, and identify that scope rather than pretending a computed one-row width describes wrapped rows. Controller can apply these Radial-only bounds in the Bar helper/padding branch without changing other family owners.

If the controller chooses one shared family-grid contract instead of categoryGrid plus numericalGrid, freeze an axis discriminator (`numerical` for Column radius-number, `category` for Bar radius-category), one resolved grid style, and one prepared `gridRadii` array. Numerical preparation selects the exact family algorithm. Painting must not choose formulas or merge axes. Controller alone renames the in-progress Column fields and updates its tests in the same join; do not dispatch an overlapping rename. The Bar radius-category line defaults false independently of its true grid.enabled; these booleans must never be conflated.
