# Ordinary table chart range: source contract

As of 2026-10-17, the original application supplies ordered column IDs and grid row ranges to AG Grid; AG Grid determines the chart category, numeric-series selection and tool-panel transformations. Source inspection resolves the application inputs below. It does not establish the original rendered category choice, drag ordering or aggregate results. Those remain browser evidence requirements before claiming parity.

## Selection and defaults

- Detached context-menu chart: `AgGridUtils.tsx:882` reads only the last `api.getCellRanges()` entry. Columns remain AG Grid Column objects; row bounds are the minimum and maximum of its endpoint `rowIndex` values. No union of multiple selections is constructed.
- `AgGridUtils.tsx:896` validates the menu using selected column IDs (or `showRowGroup`) and raw JavaScript numeric values in selected rows. `totalSeries` is the maximum numeric-key count in any collected row, not a guarantee that every row contains that many series. Scatter requires two; the other listed families require one. The selected-cell limit counts rectangular rows times selected columns. This validation does not select a category.
- `AgGridUtils.tsx:993` and `:1014` pass that range, chart type, `suppressChartRanges: true`, and `unlinkChart: true` to AG Grid. The temporary chart is destroyed after the creation callback. `hooks/useTableContext.tsx:634` supplies the owned `createChartContainer` callback.
- Integrated table/chart toggle: `Chart/hooks/useCreateChartData.tsx:21` starts from `getAllDisplayedColumns().filter(isVisible)` in returned grid order. `Chart/AgChartView.tsx:25` builds a range containing these columns and defaults the type to groupedColumn. No application rule here chooses the first category or limits numeric series.
- `hooks/useTableContext.tsx:300` prefers a stored range with more than one column unless `ignoreCellRange` is set, then widget configuration `table.chartView.cellRangeCols[chartType]`, then generated columns. Configured columns must match a definition; an empty configured result emits an error and falls back. Final column IDs are intersected with generated columns. Definitions are sorted by the selected range ID order (`:327`). Stored row bounds survive this substitution for ordinary flat tables.
- `AgGridUtils.tsx:181` infers chart category for date, Index and string values; numbers become series; other values become category. `:675` samples non-null values, chooses the majority JavaScript type, and respects explicit chartDataType (`:712`). This is type annotation, not evidence of which category AG Grid finally charts when several exist or none is selected.

## Displayed rows, raw values and hidden columns

- Detached creation reads the AG Grid chart model range (`hooks/useCreateChart.ts:151`) and normalizes its bounds. It traverses client-side nodes with `forEachNodeAfterFilterAndSort`; server-side uses `forEachNode` (`:175`). `getSelectedRangeData` (`:20`) includes bounds by `node.rowIndex` and accepts ordinary leaf data only when `node.displayed && !node.group` (`:58`). This expresses displayed-row selection with raw `node.data` values; it never reads rendered DOM cells or calls `getValue` for ordinary leaves.
- The default collector discards object-valued fields. Grouped paths instead construct rows from group keys and aggData/groupData; they are not equivalent to flat leaves (`hooks/useCreateChart.ts:60`). Server-side expanded groups and unavailable row coverage require separate runtime evidence.
- `Chart/utils.tsx:428` copies source values, with special handling for percent/normalizedPercent and titleCase/hoverCard definitions. It calls `colDefFormatter`, extracts hover-card cell values, and strips nonnumeric characters back to Number when the original datum was numeric. Therefore detached chart extraction is neither universally raw nor universally the displayed string. The exact financial scaling of a concrete formatter must be checked against that formatter and an example.
- `Chart/utils.tsx:545` identifies configured hidden and excluded columns. Final detached columns omit these (`:667`); a date field found in the extracted data is prepended when absent (`:636`). When an Index is selected alone, processing can append other non-hidden keys (`:407`). Extracted detached rows containing a date field are sorted by that date: descending only if the supplied grid API reports descending, ascending otherwise (`:644`). Detached creation calls getChartData without gridApi (`hooks/useCreateChart.ts:202`), so that branch sorts ascending even if the original table date sort was descending. Non-date detached rows retain collector order.
- Ordinary non-transposed integrated view returns early from getChartData (`Chart/utils.tsx:602`), with no replacement rowData. `hooks/useTableContext.tsx:362` only installs transformed rows/definitions for real transpose or a custom chart. The ordinary integrated chart stays attached to the existing grid. Exact AG Grid filtering, valueGetter/valueFormatter, hidden-column treatment and live updates after this handoff require runtime evidence; the application does not extract rendered cell text for this path.
- Dynamic visibility is explicitly applied to integrated default columns. Detached output filters configured hide/excluded flags; whether a dynamically hidden column can remain in a selected/model range is not settled by these call sites.

## Range, reorder and tool-panel state

`hooks/useUpdateColumnState.ts:62` builds a state address from period, transpose, selectedGroup, reversed, sheet name, selectedRatio and pivot status. `:84` resolves chartModel from addressed storage, then root storage. Range precedence is addressed per-chart-type cellRange, then model cellRange. `:319` saves matching integrated chart range events into `storage[stateKey][chartType].cellRange` only while chart view is enabled. `:107` reconciles removed/new columns by removing missing IDs and appending new IDs; it does not reorder existing IDs to match grid order.

`Chart/hooks/useChartOptions.tsx:433` retrieves the current model from AG Grid on options events and saves the model and merged options under the addressed state. On chart-type change it reapplies the stored range and current `switchCategorySeries` (`:457`). `Chart/AgChartView.tsx:34` passes `!!chartData.transpose || chartModel.switchCategorySeries`, model aggFunc, seriesChartTypes and seriesGroupType to AG Grid. Thus Switch Category/Series and Aggregate consume library model state; no owned implementation of their UI calculation or aggregate menu was identified in these ordinary-table call sites. Do not substitute a guessed transpose matrix or aggregation policy.

Series reordering has an application input contract: ordered model/range columns and definition ordering. Whether a tool-panel drag changes range columns, seriesChartTypes or another internal order, and which event persists it, must be captured from the original runtime. Saving a model on an options event is not proof that every drag or aggregate edit emits that event.

Detached storage differs: `hooks/useCreateChart.ts:238` stores chartData and the original model in an ag_chart_from_table widget. `AgChartFromTable.tsx:98` recreates using saved type, saved cellRange when present, and transpose; it does not forward model aggFunc or seriesChartTypes in this creation call. Its range callback (`:139`) saves root cellRange or transposed_CellRange; its options callback (`:298`) saves type/options and only merges chartType into the stored model. This asymmetry must remain visible in parity testing.
