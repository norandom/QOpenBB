# Separate tab navigation from chart-family changes

The [eight-case plan](../../../artifacts/reviewed/ui-parity-family-navigation-plan/plan.md) compares a tab-only detour with the same detour plus a family change. Both directions, Grouped Column to Line and Line to Grouped Column, run in matched dark/light cases. This addresses the confound in the [earlier navigation evidence](chart-ui-navigation-findings.md); it does not supply new runtime results.

Each future case starts from a fresh context with synthetic per-family ranges. Grouped Column uses all four quarters and both amount series; Line uses Q2/Q3 Operating Income, 25/30 USD millions. The underlying source rows remain unchanged. The different stored ranges make restoration observable; admission must reject a seed that the original application resolves differently. Whole-table null bounds remain distinct from numeric row indices.

The plan preserves all 34 previously inventoried thumbnail buttons and their existing conditions. It activates only Grouped Column and Line. A DOM inventory or local dependency predicate is not proof of support, visibility or successful activation in every theme or family.

The [independent review](../../../artifacts/reviewed/ui-parity-family-navigation-review/review.md) is the source-plan gate. Collector preparation must establish finite projection sizes and exact action/event linkage before a runtime grant. Full family commands, save/reopen, candidate UI and deployment acceptance remain open. Keep the existing session, widget storage and renderer owners, with no hidden or disabled replacement controls.
