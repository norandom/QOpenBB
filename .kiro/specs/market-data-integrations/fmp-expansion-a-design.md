## Query and response contract to freeze

All eleven HTTP service operations require explicit `provider=fmp` and exactly one nonempty symbol, normalized with the accepted EnterpriseValues single-symbol validation (maximum 50 characters). The generated native Python SDK retains existing provider resolution, as the umbrella design already distinguishes from REST policy; acceptance calls select FMP explicitly and retain the actual provider in output. Reject comma lists, control/query-injection syntax and repeated/malformed HTTP scalar inputs before I/O. Symbol means provider listing identity; no search/profile request or issuer inference is added. One upstream request maximum per valid execution, no automatic retries, symbol fan-out, date-window splitting or pagination loops. Retained archive multi-symbol behavior is intentionally not restored. This is a new FMP variant and its restriction must appear in discovery; it does not narrow other providers' variants.

Retained standard parameter shapes remain: AnalystEstimates/segments/quote/float have `symbol`; PriceTarget has optional standard `symbol,limit`; consensus optional standard `symbol`; HistoricalMarketCap `symbol,start_date,end_date`; growth `symbol,limit`. FMP makes the optional symbol required. FMP-only `period`, estimates `page` and bound/default overrides below belong on provider query subclasses, not global standards.

| Adapter group | Proposed exact FMP public parameters beyond symbol/provider | Outbound and returned bound |
| --- | --- | --- |
| Analyst estimates | `period: Literal['annual','quarter']='annual'`; `limit: int=20`, 1..100; `page: int=0`, 0..10 | Forward period/limit/page once; return at most limit rows |
| Price target news | `limit: int=20`, 1..100 | Forward limit once; no public page/auto-page; return at most limit events |
| Price target consensus | none | One request; at most one matching-symbol result; duplicate or foreign-symbol response is validation failure |
| Product/geographic segments | `period: Literal['annual','quarter']='annual'` | Fixed `structure=flat`; one request; flatten in provider outer-row/inner-label order, retain first 1000 rows; clipping may split a fiscal period |
| Historical market cap | `start_date: date|None=None`, `end_date: date|None=None` | Resolve omitted dates at acquisition: end=UTC today, start=end-365 days; require ordered range <=366 days; send from/to and fixed native limit=5000 once; local cap 5000 |
| Share statistics / quote | none | One request each; at most one matching-symbol row; ambiguous duplicates fail |
| Three growth adapters | `period: Literal['annual','quarter']='annual'`; `limit: int=20`, 1..100 | Forward period/limit once; return at most limit rows |

Accept `quarterly` -> `quarter` exactly as the accepted periodic adapter does; reject TTM/FY/YTD/other retained FinancialPeriods choices for these FMP variants. Reject explicit null limits/pages; reject unsupported parameters rather than silently dropping them through native ExtraParams. Dates are ISO calendar dates; effective_query records resolved dates as ISO strings. Growth default 20 deliberately replaces archived implicit 5 and must be documented as the new variant's contract. Parameter coercion must not allow boolean bounds. Describe/enforce the 366-day window in the date schemas and validator; do not invent an unsupported max_days metadata member.

Use existing `FinancialQueryAnnotation(provider_policy='explicit', procedural_bounds.max_symbols=1)` and `ResponsePolicy(mode='clip', limit_parameter='limit')` for limit groups; fixed `max_rows` for segments/market cap; provider response policy for singleton groups with cardinality validation. Native pagination has no invented continuation token: explicit page stays in effective_query, completeness remains unknown. Bounds report requested/effective limits, actual returned count, `truncated=true` only when local excess is observed, partial when clipped, otherwise unknown. A full native page is not proof of total completeness. Segment clipping must never imply a complete fiscal-period breakdown.

These bounds are conservative design decisions, not verified FMP service maxima. Contract freeze requires checking current official docs for exact forwarded parameter spellings and price-target limit behavior. A mismatch stops the affected endpoint; do not silently reinterpret a field or expand fan-out.

### Input admission before native filtering

Supported acceptance surfaces are the HTTP service, generated native Python SDK and direct Fetcher calls. Internal direct CommandRunner/Query invocation is not independently certified by this amendment. Existing Query.filter_extra_params warns/drops extras and cannot establish strict admission. Add a controller-owned core `openbb_platform/core/openbb_core/app/parameter_admission.py` helper and call it from the existing `app/static/container.py` at two points in `_run`: before user defaults, then after defaults and before `sync_run`. No CommandRunner, SDK generator or query-framework rewrite is needed.

Resolve route/model/provider through installed native descriptors and RegistryMap. Only the eleven selected FMP query subclasses opt in with strict `extra='forbid'`; other variants preserve behavior. The first pass examines supplied extra key membership and supplied invalid null/bool values before defaults can overwrite them, without requiring absent fields, inserting defaults or mutating input kwargs. The second pass validates effective standard/provider values after configured defaults. The first pass must reject an explicitly unsupported extra even when its value equals a native default. Direct Fetcher raw dictionaries validate against the same strict selected query model.

Extend the existing root HTTP policy through `services/data-api/qopenbb_data/financial_query_policy.py`, called by `financial_policy.py` before upstream dispatch. Use the selected installed query schema, canonical fields/accepted aliases and the command's actual control descriptors; reject unknown/provider-unsupported keys and repeated scalar query parameters before FastAPI defaults/filtering. Keep native controls separate from financial parameters: permit only those present in the concrete command/dependency signatures, with an explicit reviewed list for `chart`/`chart_params` where available, never the union of other providers' parameters. Return the existing safe invalid_parameters/HTTP422 envelope. Do not echo raw values or credentials. Both HTTP and SDK checks are side-effect-free and make zero provider calls on rejection.

Controller owns this admission prerequisite and tests under root `tests/providers/test_fmp_parameter_admission.py` plus `test_financial_query_policy.py`. Cases cover HTTP repeated symbol/page, unknown and selected-provider-unsupported keys including explicit default values, explicit null/bool before configured defaults, effective invalid user defaults, direct Fetcher extras, valid native controls and unchanged baseline variants. Test public generated SDK entry as well as mounted HTTP; a direct helper test alone is insufficient. Adapter tasks depend on independent acceptance of this prerequisite and the schema characterization task.

## Typed row and financial meaning

Reuse each existing standard Data class and archived provider-specific field declarations/aliases, reviewed against stable payload fixtures. Public row field set is the union of that existing standard and the selected retained provider Data class, without opportunistic new fields. Freeze the concrete validation/serialization JSON schemas as reviewed fixtures before adapter fan-out. Provider rows are validated with existing `validate_financial_result`; all adapters return `AnnotatedResult[list[Data]]` using existing `FinancialResultMetadata` v1 at `extra.results_metadata.__qopenbb_financial__`.

Do not add currency, forecast-vintage, source-row-ID, continuation or period-duration fields to core metadata or public row schemas in this slice. If absent from the retained schema, disclose unknown currency/basis in existing metadata rather than deriving it from symbol/exchange/profile. Any necessary public schema extension requires an explicit reviewed schema diff and downstream compatibility decision before the affected worker starts. Existing financial annotation templates must cover every declared result field, including provider-specific ones; undeclared dynamic fields are not the escape hatch.

| Dataset | Required meaning and annotation decisions |
| --- | --- |
| Estimates | `date` is forecast fiscal period end, not publication/as-of time. Amount estimates currency scale 1, EPS currency/share, analyst counts count; `value_origin=estimate` is supported by the existing enum. Provider documentation says inputs may mix analyst inputs, manual adjustments and internally projected fields: no blanket direct-analyst-consensus lineage claim. Vintage/publication/duration unknown; point_in_time_safe=false. Preserve low/high/average/count separately; do not synthesize missing consensus. |
| Price targets | Individual event `published_date`/`published_time` retain precision and timezone actually supplied; target/posted-price currency/share; target is estimate, posted price provider observation. Preserve analyst attribution and adjustment fields; no summary substitution or invented timezone. |
| Target consensus | High/low/median/consensus remain distinct; estimate origin; valuation/as-of/publication date and currency unknown unless explicit retained fields supply them. Retrieval time is not consensus date. Published FMP FAQ methodology (checked 2026-11-17): past six months, latest target per analyst company, daily recomputation. Record this dated documentation as a limitation/source explanation; response-specific aggregation membership, timestamps and lineage remain unverified. |
| Segments | Preserve period_ending, fiscal_year/period, filing_date, exact business_line/region labels; revenue currency scale 1, provider observation. Retain duplicate labels across parsed source rows, source order and unknown currency; duplicate keys already lost by JSON parsing cannot be recovered. Flattening preserves period-to-label association; no sum/reconciliation, taxonomy normalization or claim of exhaustive/disjoint categories. |
| Historical cap | date is capitalization observation date; market_cap currency scale 1, provider_calculation. Share count, price basis and currency may be unknown. No division to infer shares. |
| Float | outstanding_shares and float_shares use shares; free_float is a ratio with scale 1, dividing the provider percentage by 100 with a declared transformation. Preserve zero and null separately; repair the archived zero-to-null defect. Fixture characterization confirms the source convention and stops on contradiction. Provider-calculated ratio versus observed counts; no date is filled from retrieval time. Nullable date compatibility is characterized before schema freeze. No substitution of quote shares. |
| Quote | Map last price/timestamp and OHLC/volume to retained meanings; prices currency/share, volume shares, market cap provider_calculation. Explicit Unix timestamp conversion declares UTC only when source epoch semantics support it. Bid/ask/close/previous close remain distinct; zero and null remain distinct. No quote-date assertion for market cap/shares. |
| Growth | period_ending/fiscal fields retained; numeric growth fractions `unit='ratio', scale=1`, provider_calculation, never multiply by 100 for presentation. Denominator/source periods, restatement and discrete/YTD methodology unknown unless explicit source facts establish them. Balance growth compares stocks; flow growth does not establish discrete quarters. |

Required date/value fields in retained standards (estimate date, segment period/revenue, cap date/value, growth period end, target publication) remain required: missing/null/malformed required facts produce safe response-validation failure, not invented dates, zero or silent row dropping. Optional dates remain null with missing availability. Empty arrays are a distinct successful empty result. Unknown fields stay unknown; source row order is preserved except deterministic date sorting explicitly documented per adapter. Do not deduplicate financial observations by date alone.

Reuse `FMPAcquisition`, safe helpers with `with_provenance=True,typed_errors=True`, URL encoding, common error taxonomy and existing availability rendering. Preserve retrieval time/source endpoint/effective query and source facts available in declared rows. Existing observation_provenance is for FRED realtime intervals, not a new arbitrary row-provenance store. Source.documentation must use a credential-free query/fragment-free URL; FAQ URLs with query strings remain document citations only. Secret-safe failures cover authentication, entitlement, rate limit/retry-after, timeout and malformed responses. No provider-specific exception strings reach consumers.
