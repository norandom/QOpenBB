## Accepted design boundaries

The own `kind` check plus independent family check is appropriate for already validated retained captures. Keep ordinary contexts scalar-only and construct hierarchy contexts explicitly. The capture-free frame extraction removes fake captures from initialization/range/baseline helpers without broadening ordinary projection contracts. Guarded context construction must reject a family/capture mismatch before preparation; a type assertion is not evidence of that guard.

The recapture design correctly reads the grid before `owner.transact`, then repeats selection/transition against the current Widget inside the replayable transaction. It checks address, generation, data/render stamps, latest range/configuration and assignment identity; exact ordered category vectors and retained/requested numeric descriptors remain mandatory. Project prospective arithmetic before one storage/local/capture commit. Keeping current arithmetic out of the transaction precondition is necessary so an overflow state can recover through removing fields or turning aggregation off. Full model replacement is justified for deleting `aggFunc`; preserve inactive aggregation with no categories and unknown option fields.

No-size and multicategory handling, count units, separate setup intent, dedicated hierarchy Customize composition, skipped axis/categorical-legend side effects, and explicit capture invalidation on family transitions align with H1/H2. The common commit envelope must actually allow capture to be cleared on a family change; the existing dispatcher currently spreads `committed.capture` and adds a data revision, so it must branch rather than manufacture a partial capture from `undefined`. This is already inside the planned atomic boundary, not a new owner.

Theme palette projection from the same selected theme, hierarchy parameter layering before explicit overrides, and original generated labels/tooltips/bottom padding are correctly assigned to caller owners. Keep the grid-provided override precedence already present in `useCallerSessionInputs`. Light/dark/custom tests must assert effective tokens/options, not only theme names. The plan appropriately leaves advanced-fill acceptance to H2's explicit unsupported/adapter contract and does not invent a flag or fallback renderer.

The hover binder/lifecycle division is sound: one native listener set per instance, stable data ID and series ID, finite marker validation, no coordinate guessing, no coupling to tooltip enabled state. Resize must invalidate the plan, including when `apply(pending, true)` performs a forced render of the old request; that forced render must not reinstall the old viewport plan. New plans become active only after a fresh accepted render. Stale requests retain the accepted plan. Error cleanup must detach the instance and invalidate export even if listener removal/marker clearing throws. These are implementation review obligations under the plan's existing contract.
