## Review the two changed responsibilities

[failure-metadata.mjs](harness/failure-metadata.mjs) extracts message once, accepts only a string, classifies the exact budget sentinel before redaction, and measures the complete four-field JSON object in UTF-8. A complete redacted message survives when it fits; oversized or unavailable messages use the reviewed fixed forms. Tests verify both origins' fallback bytes, ASCII and escaped/multibyte boundaries, unpaired surrogates, empty/nonstring messages, throwing getters, no nonstring coercion and exact nonempty synthetic credential substitution. This bounds retained serialization; it does not bound allocation or hostile getter behavior.

[journey.mjs](harness/journey.mjs) uses the formatter in its case and outer catches. The case catch keeps status classification and the original remaining targets/modes, with fixed remaining-probe reasons. The outer catch preserves existing case-origin fields, adds at most one outer metadata object, and copies exactly those four first-case fields into the standalone failure receipt. No exception is re-extracted for that copy. The receipt reports only a normal closing write return as succeeded. Any failed closing write is write-unverified because the unchanged writer exposes no trusted prewrite-stage token. Setup/preflight closure reports not-attempted for the case write. The reserved rejected-prior-prefix enum is consequently not emitted by this source; prewrite preservation in a mock is an independent observation, never inferred from error text.

The [source diff](source.diff) and [source hashes](source-hashes.json) identify the change from the [accepted harness](../ui-parity-tooltip-segment-keyboard-revised/harness/journey.mjs). The full base copy is byte-identical. The only changed pre-existing harness file is journey.mjs; failure-metadata.mjs is new. IO, input/probe logic, retention, the R01 exhausted-settlement correction, fixture, financial/identity/tooltip observations, routes, lifecycle and cleanup retain their base bytes. The 32,768 input reservation, 115,072 guard, 16,000 final tail, 131,072 case ceiling and all other contract constants remain unchanged. The copied historical static-check script predates this change and is not presented as a verification command for the new catch text.
