## Implementation seams

Paths in this section are relative to `vendor/workspace/terminalpro/`.

**Preview derivation.** Keep `chartThemeState.ts`, `useChartSettings.ts`, `ThemeSettingsLayout.tsx`, `ChartPaletteControls.tsx` and `ChartParameterControls.tsx` as the state/control owners. `chartThemePreview.ts` becomes a pure ECharts request builder with small adjacent appearance, sample or layout modules where useful. Its inputs are immutable draft, mode, measured viewport and current legend selection; its output contains options and typed interaction plans, never persisted renderer state. The wrapper supplies increasing revisions and a mode/session legend scope. Apply full option replacement through the accepted lifecycle; removed series cannot survive an update.

Resolve a finite preview-specific parameter map from pinned AG defaults. Keep explicit field precedence and base-theme fallback semantics; do not reuse the incomplete application projection or add a second theme store. Preserve text escaping in custom tooltip and accessible content. Invalid CSS colors, unsupported paints and invalid numeric geometry must be explicit preview errors that recover when the draft becomes valid, without disabling Save or mutating the payload.

**Generic legend extraction.** Extract the reusable grid packing/layout from `echarts/pieLegendLayout.ts` into a neutral legend module. Input carries plain items `{key, label, enabled}`, viewport, padding, caption space, legend style and an ID prefix. Output retains native legend components, graphics, footprint and the existing pagination-plan shape. Keep `pieLegendLayout` as a thin adapter from Pie rings/style to that neutral input so existing Pie/Donut behavior is unchanged. The preview passes real bar-series items; it must not construct fake Pie assignments/rings or call Pie mapping to obtain a legend.

The existing pagination binding already owns page/anchor state and accessible DOM mirrors. Extend that owner with optional focus colors and a typed preview interaction policy for roving arrows, hover/focus and isolate/restore; defaults preserve existing Pie/Donut callers exactly. The preview always supplies this required policy. It is an internal compatibility contract, not a user setting or capability flag. Double-click isolation is implemented only for the preview in this slice. Reuse its selected-state projection and error channel. Active/inactive page colors must be separately resolved rather than an unconditional opacity approximation. Avoid a second native/DOM selection store. A native single-row scroll legend or clipped wrapping legend is not equivalent to the observed grid/paging contract.

**Chart-point keyboard binding.** Add one opt-in typed `keyboardNavigation` plan to `ChartRenderRequest`; retain the public `EChartsHostHandle` export-only surface. The initial supported plan is explicitly grouped vertical bars: ordered series IDs/names and category/value records, grid/axis identities, resolved focus styles, and the same explicit bar width/gap geometry used by the renderer. This is a rendering contract, not a general application action callback.

Bind it inside the existing lifecycle using a small dedicated module. That module owns the plot's DOM focus/announcement and current point, with internal narrow ports for selected-state lookup, public `convertToPixel`, highlight/downplay and showTip/hideTip. Derive bar bounds from the shared explicit grouping geometry and public coordinate conversion; do not inspect ECharts private models or DOM canvas pixels. A targeted engine test must prove focus bounds track the correct bar after series toggle and resize. No ECharts instance or arbitrary dispatchAction method escapes the host.

The lifecycle alone mounts, updates, resizes, reports interaction failures and disposes all bindings. Keyboard synchronization follows the accepted request and legend projection, including hide-all recovery. A stale callback cannot act on a newer revision or disposed instance. Existing hierarchy/pointer/navigation bindings retain their current behavior. Extract cohesive lifecycle wiring if the added work would exceed caps; do not duplicate initialization, ResizeObserver, export or disposal in a preview-specific host.
