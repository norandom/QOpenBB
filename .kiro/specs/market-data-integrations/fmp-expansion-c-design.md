# FMP Batch C design for provider valuations and as-reported statements

Expose two FMP provider valuation references and three issuer-reported statement families through the existing native command, HTTP and consumer catalog surfaces. The [approved expansion plan](fmp-expansion-plan.md) defines the five operations. This design proposes a bounded contract and identifies the source evidence required before implementation.

## Public query contracts

REST paths below follow `/api/v1/equity/fundamental/`. The SDK uses the equivalent `obb.equity.fundamental` command. REST and the generated consumer require explicit `provider=fmp`. The generated SDK retains native provider resolution with no fallback after selection. Require one nonblank provider symbol, normalized using the accepted single-symbol policy. Apply the exact selected variant at HTTP and SDK entry and direct Fetcher admission. Reject repeated scalar HTTP inputs, unknown parameters, unsupported provider/period options, multiple symbols, explicit null inputs and invalid numeric types before transport. Accept wire strings only through the documented HTTP conversion for the selected type. Extend `financial_query_policy._http_value` for the beta variant to recognize bounded ASCII decimal tokens with optional sign, decimal point and exponent. Parse with exact decimal arithmetic for validation. Preserve the admitted HTTP token through native dependency parsing, effective-query metadata and FMP forwarding, including zero and trailing zeros. Reject alphabetic, blank, nonfinite, repeated and out-of-range values before transport. In typed SDK and direct callers accept finite `Decimal`, integer and float inputs in the admitted range, with booleans and strings rejected. Serialize `Decimal` and integers exactly. For floats, use the shortest round-tripping decimal representation of the value received and document that an already-rounded caller float cannot convey additional digits. Use `Decimal` for exact authored decimal input.

The statement contract proposes forwarding `symbol`, `period` and `limit` in one request, with no date window, TTM, field selection, local amendment selection or pagination. Confirm both wire frequencies and limit support separately for all three endpoints. Preserve validated provider row order up to the admitted limit. Record effective query, observed/returned counts, known clipping and source completeness unknown where no provider continuation or completeness evidence exists. Hitting the upstream limit alone cannot prove clipping or completeness. If required forwarding semantics fail, reopen that route before model or schema acceptance.

Use the existing safe stable FMP acquisition and financial error policy with server-side credentials, GET, bounded timeout, no redirects, retry loops, automatic supplementary calls or provider fallback. An admitted call can make at most one send. Only an actual successful top-level empty array can use the accepted empty-list opt-in. Preserve an empty AnnotatedResult and acquisition metadata when serialized as successful JSON. A typed missing-data outcome projects to an empty HTTP 204, which carries no acquisition metadata. Freeze and test both reachable outcomes on the mounted route. The consumer must never fabricate metadata for 204. Null fields, an absent tag, an empty acquisition and a malformed/failed response have distinct meanings. Validate every source row before clipping. Reject wrong symbol, unexpected nonempty shape and malformed required fields with typed invalid-response errors. Keep the existing explicit absent-payload classification documented separately. Preserve authentication, entitlement, throttling, timeout, upstream failure and safe retry interval under the existing error contract. ## Financial results

Use typed data plus `AnnotatedResult` and existing financial metadata for provider, actual retrieval time, effective query, field origin, units, limitations and bounds. Preserve source amounts at the supplied scale and precision. Explicit zero is a value. Optional unknowns stay null or, for omitted native tags, absent. Reject numeric nonfinites and malformed known values. Preserve supplied date precision and timezone when present. Compare dates with their own financial meaning. Observation date, filing date, acceptance timestamp, valuation date, provider year, and time acquired serve different purposes.

### Exact numeric transport and presentation

All five adapters must see the provider body before ordinary JSON decoding can round decimal values or overwrite duplicate members. Use an explicit Batch C opt-in on the existing FMP acquisition path. Read up to 4 MiB of the decompressed body, reject duplicate object members at every depth, reject nonfinite JSON constants and enforce a maximum of 32 nesting levels and 128 characters per numeric token. Apply the admitted response bounds and the statement limit of 4,096 facts per row. Fail a violated decoding or fact bound as a safe invalid response. Keep existing default decoding for other adapters.

Preserve raw JSON number tokens while decoding and project exact tokens as JSON strings with a numeric kind of `integer` or `decimal`. Apply this representation to monetary values, provider DCF assumptions and outputs, share counts and numeric statement facts. Keep text and actual booleans distinct and explicit null separate from omission. The token preserves source precision. Financial unit and scale come from evidence. Identity fields such as a validated four-digit fiscal year can use a bounded integer. The installed payload, generated schemas and Workspace must agree on the exact token representation. If a renderer offers a rounded display, preserve the original token for inspection and copying. Never use rounded values for comparison or to establish beta binding.

Verify raw-body parsing, SDK/REST serialization and browser fidelity for `9007199254740993`, precise decimals, zero, null, omitted facts, duplicate JSON members and conflicting facts under repeated complete filing identity. Exercise near-but-unequal request/response beta through mounted HTTP, SDK `Decimal`, direct Fetcher and Workspace. Confirm the request token forwarded and result tokens remain exact even when a display rounds the pair to the same number. Compare successful empty-array JSON and the typed missing-data HTTP 204 projection with malformed and duplicate-row responses.

### FMP valuations

- Standard DCF maps exact `symbol`, `date` and `dcf` to listing identity, provider valuation date and provider DCF value. Require the exact selected symbol, valid civil date and finite value when a row is present. Expose valuation as a provider model output and identify a per-share basis only with provider definition evidence linked at freeze. If `Stock Price` or another price alias is observed, retain it only after freezing the source key, basis and limitations. Market observation date stays unknown absent explicit evidence.
- Custom DCF requires exact selected `symbol`, a four-digit `year` and finite `equityValuePerShare` on every row. A digit string and a corresponding integer map to the same year identity and cannot form two rows. Reject duplicate symbol/year identities, retaining provider order of valid rows. Treat `year` as the provider's year label. Describe historical versus forecast years only where FMP identifies the basis. Preserve a separately supplied valuation date. Leave it unknown if the provider supplies only year labels. Record valuation and any reference price as distinct values.
- Preserve documented and observed custom inputs and output detail with exact source keys frozen per field. Provider-returned assumptions include `beta`, `wacc`, `riskFreeRate`, `marketRiskPremium`, `costOfEquity`, `taxRate`, `longTermGrowthRate` and supplied operating assumptions. Candidate outputs include `enterpriseValue`, `equityValue`, `ufcf`, `terminalValue`, `netDebt`, `totalDebt`, `totalCash` and `dilutedSharesOutstanding`. Track value, source key, unit/scale and basis. A percentage-looking field keeps its raw number and unknown scale until verified. Record the equity/debt/cash, lease, minority-interest, share-count and market-date bases where known, preserving unknowns. A numeric share count does not identify the adjustment convention. Treat `costofDebt`, `revenuePercentage`, `depreciation` and `depreciationPercentage` as distinct exact keys pending definition and scale evidence. The freeze must list retained fields and explicitly account for observed fields that remain unmapped.
- Use explicit provider currency only when it applies to the mapped field. Leave valuation currency unknown if absent. The November 6 MSFT direct observations supply no valuation currency for either operation. Neither listing, profile, reported-statement currency nor retrieval time fills a valuation gap.
- Beta is the sole proposed override. Characterize default and override with matched unique issuer/year sets. Record the requested beta token separately from each returned beta token. Determine echo by exact decimal numeric equality, with no tolerance or float conversion. Thus `1.0` and `1.00` bind to the same value while `1.00000000000000001` and `1.00000000000000002` differ. Indicate exact observed echo, mismatched echo or unavailable confirmation. An unusable adjusted payload, lack of documented binding, or missing/mismatched beta echo blocks the override at characterization. A reviewed default-only custom contract may proceed if its source evidence is sound and its generated catalog omits beta. Reopen review before exposing an override. A matching echo establishes only source acknowledgement and leaves the effect on the calculation and sensitivity unverified. No secondary baseline request occurs during a normal user query.

The November 6 MSFT checks establish standard date and value availability, custom year/value rows and an echoed beta of 1.0 in a paired observation. Raw captures are unavailable in the current workspace. This evidence supports characterization priorities and leaves native route, current entitlement, units and browser behavior to be verified. ### Issuer-reported statements

The existing `ReportedFinancialsData` replaces zero with null. Keep its existing route and Intrinio contract. The normalized statement routes retain their [statement-period v1 contract](../../../docs/reference/statement-period-provenance.md), including its fact allowlist and discrete-quarter derivation rules. Batch C as-reported routes use their own statement and per-fact context. Use three distinct model pairs with a shared, lossless statement envelope and a fixed statement kind per command. Retain the exact native tag strings and associated supplied values in a typed fact collection. Keep a dynamic tag collection separate from fixed result fields. The freeze specifies actual source envelope paths, admitted fact shapes and JSON number fidelity using sanitized wire evidence. Preserve source numeric, text, boolean and null semantics where the source provides those kinds. No normalization, truthiness filtering, broad flattening, whole-payload passthrough or tag-name-based inference. Reject unsupported malformed fact structures without silently dropping facts.

| Identity or financial basis | Required public behavior |
| --- | --- |
| Issuer and listing | Require the response symbol to match the normalized selected listing. Retain source issuer identifiers such as CIK as strings when present. Keep provider symbol, issuer and statement kind separately. |
| Fiscal and document identity | Require a valid period-end date and an explicit supported fiscal period label in the source. Preserve source label and available fiscal year, filing date, acceptance timestamp, accession/document identifier, form, amendment/restatement indication and validated source link. Keep source-distinct vintages even when period ends match. Preserve distinct rows if source identifiers are missing and identify unresolved vintage identity. Reject repeated complete filing identities as invalid responses. Test exact duplicate rows and conflicts under the same complete identity separately. Distinguish rows with unresolved filing identity from repeated complete identities and preserve their source order. Never silently select a latest filing or claim a vintage history. |
| Annual and quarterly selection | Preserve selected frequency and observed fiscal label separately. `annual` expects fiscal year-end labels and `quarter` expects fiscal quarter labels supported by evidence. A mismatch fails validation until an exception is characterized and reviewed. Keep period start and end, source duration and year-to-date basis wherever supplied. Query frequency alone does not identify the duration of each fact. |
| Income and cash flow | These are duration statements. Mark the supported per-fact duration as annual, discrete quarter or year-to-date only from source evidence. Otherwise retain unknown duration. A fiscal quarter label does not convert cumulative cash flow into a discrete quarter. Preserve instant facts such as beginning/end cash if explicitly identified. |
| Balance sheet | Preserve the statement instant at period end and any distinct per-fact source context. Annual and quarterly balance sheets are snapshots even when they refer to different filing frequencies. |
| Native fact | Preserve exact tag, value, available taxonomy/namespace, context, dimension, unit, scale and currency. Unknown units and currency stay unknown. Apply a statement-level reported currency to a fact only if supported by its unit/context. Never assume monetary units for counts, ratios or per-share values. Preserve source-provided facts and formatting meaning without assigning normalized accounting equivalents. |

Include annual and quarterly fixtures for all three operations, with finite amounts, actual zero, explicit null, omitted facts, source-period conflicts and same-period distinct filings. Include a balance instant, a quarterly cash-flow observation with proven YTD or unknown duration, and a real non-USD observation if the selected provider coverage permits. If source duration, reporting currency, amendment or availability date is absent, show that gap explicitly and keep point-in-time eligibility unverified.
