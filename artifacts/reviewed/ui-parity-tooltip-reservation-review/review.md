Source review confirms that case status/reason/remaining-mode additions and the outer reason replacement lie outside the bounded input-entry object. ## Completed objects and physical prefixes differ

The independent [audit](audit.mjs) exercises the actual IO writer in a review-owned temporary directory. A rejected 132,270-byte completed object leaves the preceding 88,448-byte file byte-for-byte unchanged. Executing the actual outer catch afterward replaces its long reason with `Case JSON bound` and can successfully persist a 104,661-byte unresolved record, including the tail. Thus a failed terminal write does not imply that an oversized file was written, that the physical prefix equals the last in-memory count, or that the prior prefix necessarily remains the final file forever. The original large reason is absent from that smaller recovery record.

This distinction does not rescue the candidate proof: the claimed complete record failed to fit, and fallback replacement is not a bound on all first exceptions. The report correctly treats rejection as a preservation safeguard and distinguishes source-admissible fixtures from demonstrated runtime states. No report correction is required.

## Smallest prerequisite for another source proposal

Propose one explicit serialized failure-metadata policy shared by the case and outer catches, covering exceptions outside `input()` as well. Bound metadata before assignment. A possible policy is to retain a complete message only when it fits a reviewed byte cap and otherwise store a fixed unresolved reason code with an explicit omission flag. Specify how the counted action and prior persisted prefix remain truthful. Do not silently truncate financial values, identity or tooltip content. This is a proposed contract for review, not permission to implement it or an endorsement of a particular cap.

Then derive or enforce the entire intervening scaffold: key and array punctuation, mode/baseline wrappers, counter/status replacements, image references, remaining-mode fields and failure metadata on successful and throwing paths. Keep the final 16,000-byte tail and global writer limits separate. Challenge both the attempted complete terminal write and its outer-catch replacement, with escaped text and failures after input. Only after that finite interval proof and independent review should a smaller reserve be considered. The accepted 32,768 reserve also does not guarantee complete arbitrary-error retention; retaining it avoids an unsupported change rather than certifying a universal bound.
