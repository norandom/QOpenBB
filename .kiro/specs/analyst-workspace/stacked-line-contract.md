## Numerical and data contract

Inputs are the immutable post-Set-Up `ChartSnapshot`, ordered selected numerical columns, exact variant, and optional legend membership keyed by stable column ID. Reuse admission for unit/currency/scale compatibility, source shape and ordinary Set Up witnesses. Percent coordinates do not waive unit checks. Never store cumulative coordinates, percentages or runtime legend membership in financial observations.

Resolve effective category axis type before projection. Ordinal `category` uses raw row index as its group key, preserving duplicate labels. For `number` and `time`, reproduce Grid-processed coordinate serialization from [grouping source](../../../artifacts/reviewed/chart-stacked-line/grouping-source.md): time leaves data untouched when first value is Date; otherwise strings become Date and nonstrings remain unchanged. Object keys use JSON.stringify, primitive keys use original string coercion. Equal Date instants group; raw epoch numbers remain distinct from Date keys at the same pixel coordinate. For each group traverse selected series outermost and original group row indices innermost, accumulating signed finite contributions from zero. Hidden or missing/nonfinite values contribute zero. Record `C[j,r]` at original series ID and row index. Unique x reduces to `C[j] = sum(v[0..j])`. Do not split positive and negative stacks. A hidden or missing raw observation has no marker, label or tooltip datum, even where its zero substitution contributes to a later valid series. A finite raw zero is a real datum.

For `stackedLine`, draw each enabled finite raw observation at its `C[j]`. For `normalizedLine`, use `D = max_j,r(abs(C[j,r]))` across required endpoints in the group, including the zero start, and draw `100 * C[j] / D`, bounded to [-100,100] for rounding only. This is maximum cumulative excursion within one accumulation group, not gross absolute contribution or final total. It is order-sensitive. If `D == 0`, draw null for every normalized endpoint: no invented zero marker or tooltip hit. Raw zero remains stored and the category remains present. A raw zero with positive D draws at its cumulative endpoint and retains raw zero labels/tooltips.

Discriminators: `[60,-80,20]` gives `[60,-20,0]`, normalized `[100,-100/3,0]`; `[60,-20,60]` gives `[60,40,100]`, normalized `[60,40,100]`; `[-20,-30]` gives `[-20,-50]`, normalized `[-40,-100]`. Hiding or reordering a series recomputes main prefixes, denominator and finite extent. Derive extent from admitted visible cumulative endpoints, without forcing zero into a positive or negative domain; retain ordinary Line axis niceness/rounding. Original positive financial samples begin above zero (stacked approximately 40 billion, normalized 50%). Stable legend IDs and selected order survive duplicate display labels. Navigator overview retains the full selected-series context.

Missing raw points remain null in drawn data. `connectMissingData:true` connects surrounding admitted endpoints without creating visible zero points; false breaks the affected line. Missing lower contributions are zero for later finite endpoints. Do not synthesize labels/tooltips for missing observations. These zero/missing policies are explicit source-compatible choices from dependency scalar Line handling; the original review did not numerically prove painted zero/missing geometry. Candidate numerical/SSR tests must verify them, and targeted original comparison must resolve a material topology discrepancy before SL3 acceptance.

All coordinates and extents must remain finite. Normalize with a common finite scale before summation/multiplication when necessary, so finite inputs such as `[MAX_VALUE,MAX_VALUE]` can produce normalized `[50,100]`. Do not overflow by multiplying a prefix by 100 first. Preserve ordinary arithmetic rounding when safe. For unnormalized Line, an unrepresentable required prefix makes the translation invalid with a specific diagnostic and existing visible recovery; never silently clamp, omit the series or emit Infinity/NaN. Finite cancellation may be recovered with scaled summation, but every required plotted prefix must be representable. No partial chart on numerical failure. Reuse the existing diagnostic/result shape rather than throwing through the renderer.

Tooltips and labels use raw individual observations with the existing units/format callbacks. Only normalized value-axis ticks use percentages. Keep raw data indexes/category lookup aligned with drawn endpoints, including duplicate labels and nulls. The tooltip must not advertise a missing or zero-denominator null endpoint as a plotted hit.

Native category, duplicate-category, number and time support stays reachable. Reuse ordinary Set Up aggregation before projection; without aggregation preserve every row/index and ordinal coordinate path. Continuous axes retain original numerical/date coordinates, order and repeated x values. Group accumulation never merges raw rows. Number x `[1,1]`, A `[10,20]`, B `[1,2]` gives A `[10,30]`, B `[31,33]`, D=33. Repeated ordinal labels instead give A `[10,20]`, B `[11,22]`, independent D=11 and D=22. Grouped-category/pivot and cross-filtering remain outside this ordinary Table/File slice, retaining existing admission/diagnostics. Add focused original diagnostics for duplicate categories and number/time axes, then compare the retained native behavior before acceptance. A discrepancy is a join repair or documented decision for review, never permission to disable a supported axis/category mode.
