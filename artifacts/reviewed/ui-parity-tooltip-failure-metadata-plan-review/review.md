## F01: attempted writes can leave the prior prefix unverified

**Important; blocks plan acceptance.** The proposed three outcomes are `succeeded`, `rejected-prior-prefix` and `not-attempted`. The [writer](../ui-parity-tooltip-segment-keyboard-revised/harness/io.mjs) first performs explicit checks, then calls `fs.writeFileSync`. An ordinary write error can occur after overwrite begins. The write was attempted and did not succeed, while the prior bytes are not established as preserved. None of the three outcomes is truthful in that case. The plan's filesystem-crash disclaimer does not resolve ordinary write failure.

The independent audit executes that unchanged writer in a VM with an injected filesystem adapter. The adapter accepts the write, retains only 13 bytes and throws. All prewrite checks passed; the preceding simulated file differs afterward. No real file was damaged, and no collector was run. This source-level counterexample establishes the missing outcome without asserting that the fault occurred historically.

Smallest correction: add `write-unverified` for an attempted persistence failure without proven prefix preservation. Reserve `rejected-prior-prefix` for an identified prewrite rejection or independently verified unchanged prior bytes; arbitrary exception text is not such proof. Retain `succeeded` only after actual successful persistence and `not-attempted` when no case write was attempted. Account for the longest enum value in the finite receipt/scaffold proof and test both prewrite rejection and an injected write-stage failure. No atomic writer redesign is requested.

## F02: the standalone receipt does not retain the first case failure

**Important; blocks plan acceptance.** The case object preserves its first case-origin metadata in memory, but the separate failure receipt is specified to contain only the outer metadata. If the first failure was never persisted and the closing case write is rejected, the old file contains neither failure and the standalone receipt records only the closing error. The first case reason is lost from durable evidence despite the preservation objective.

The audit constructs the exact proposed receipt shape: an unchanged prior started case, an attempted case with bounded first and outer metadata, and a standalone outer-only receipt marked `rejected-prior-prefix`. Only the unpersisted attempted object contains the first reason. This is a schema counterexample to the plan, not execution of an implemented formatter.

Smallest correction: include the existing bounded first-case metadata in the standalone receipt, for example as `firstCaseFailure` or explicit null when no case-origin metadata exists. Keep the closing outer metadata separately identifiable. Copy the already formatted object; do not reread the exception, create another history, or substitute the closing reason. Count its property wrapper and at most one additional 512-byte object in the standalone receipt's finite and aggregate budget. A rejected standalone receipt must remain an explicit evidence limitation; do not claim both failures were durably retained when no successful write establishes that fact.
